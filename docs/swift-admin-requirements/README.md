# Swift 관리자 앱 기능 요구사항 정의서

기준일: 2026-10-17. 기준 구현: 이 저장소의 `LessonClient/` Swift 앱 현재 작업 파일(미커밋 수정 포함). Flutter 구현은 기준으로 사용하지 않았다.

목적은 다른 AI가 같은 관리자 업무와 데이터 흐름을 구현할 수 있게 하는 것이다. 픽셀 단위 디자인 명세는 아니며, 화면의 입력·출력·동작·API·예외·검수 조건을 정의한다. 서버를 실행하거나 운영 데이터를 변경하지 않고 View, ViewModel, Domain, DataSource, Model을 정적으로 확인했다. 서버 내부의 검색 SQL·정렬·삭제 cascade는 클라이언트만으로 확정할 수 없으므로 확정된 동작처럼 기술하지 않는다.

## AI에게 전달하는 방법

이 폴더 전체를 전달하고 다음 지시문을 사용한다.

> README, 00-common, 구현할 기능 문서, API 계약, 현재 제약을 먼저 읽어라. FR 식별자별 기능과 AC 검수 조건을 구현하라. 하위 화면과 일괄 작업도 범위에 포함하라. Word와 Vocabulary, Example과 ExampleSentence, 연결 해제와 실제 삭제를 구분하라. 검색을 임의의 로컬 필터로 대체하거나 API·서버를 임의로 바꾸지 마라. reference는 Swift 알고리즘·프롬프트의 정확한 참고 원문이다. 버그·미구현 표시는 정상 기능 요구사항이 아니다. 개선이 필요한 항목은 차이를 보고하고 결정받아라. 데이터 수정 검증은 mock/fixture로만 수행하라.

문서 내 `FR-*`는 기능, `AC-*`는 수용 조건이다. `현재 제약`은 관찰된 구현 한계이며 추가 기능 개발의 승인으로 해석하지 않는다. API 경로는 서버 기본 URL에 붙는 상대 경로다. 소스 경로는 저장소 루트 기준이다. 주요 복잡 알고리즘과 AI 프롬프트는 `reference/`에 함께 보관하여 이 문서 묶음만 전달할 때도 참고할 수 있다.

## 메뉴 기준

Swift 최상위 메뉴는 17개: 레슨 → 유닛 레벨 → Batches → 학습 단어 → 예문 → 예문 문장 → 연습문제 → 시도 기록 → 학습 큐 → 단어 상태 → 사전 단어 → Cambridge → 포럼 → 구문 → 발음법 → TTS → Sense.

`포럼`은 실제로 Word Form 관리 화면이다. 문장 유닛 검사는 독립 최상위 메뉴가 아니라 Batches 안에 있다. 토큰 상세·문장 상세·문제 생성 등은 하위 화면이다. 메뉴 개수와 기능 개수를 같게 세지 않는다.

## 검증 범위

각 문서의 AC를 mock HTTP와 고정 fixture로 검증한다. 실제 DB 생성·수정·삭제는 수행하지 않는다. 오류·부분 성공·중복 클릭·null 연결·한 Example에 여러 문장·같은 표면형의 다른 Word/Sense를 필수 데이터로 둔다. 외부 AI 결과의 문구 자체는 비결정적이므로 고정 응답을 주입해 파싱과 저장 순서를 검사한다. 문서 작성은 실행 성공이나 서버 지원을 보증하는 통합 테스트 결과가 아니다.
